# Round 2 coverage and disposition

Reviewers: `astra`, `ds4`, `glm`. All three produced usable reports, all on
their primaries; no failovers and no execution errors.

No HIGH or CRITICAL findings. Two MEDIUMs and five LOWs, all addressed in the
commit that follows this record. The round re-read the whole M4 scope rather
than only the round-1 fixes.

The MEDIUMs:

- `ds4` and `glm` independently: `PolicyRead.Raw` still put pointers into the
  caller-visible map after the round-1 fix stopped at `client.go`. A `*string`
  for `sampled`, a `*string` for a debug `thought`, and a `map[string]*float64`
  for a component's `top_logprobs` all marshal to the same JSON as the value
  behind them, so the parity gate cannot see them; a caller can, as an address
  or a failed type assertion. `stringOrNil` and `optionalFloatMap` now dereference
  them, and `assertNoPointers` walks a caller-visible value through reflection so
  a nested `map[string]*float64` is caught rather than skipped because the map
  itself is not a pointer. Both regressions fail the walker when reverted.
- `glm`: a repeated label in a multi-label head was accepted. The head becomes
  one noul per label under the key `head:label`, so the second read answers the
  same question under the same key; the view drops the first answer and
  `Raw["head:label"]` is left as the zero answer. Python pops the key once and
  then raises `KeyError`. This port now refuses it in the validation pass, before
  any request goes out, which the test pins by asserting zero requests spent.

The LOWs:

- `ds4`: the client fixture's recorded date, fingerprint and tokenizer
  revision were never checked against the fixture, and the fingerprint check was
  a shape test that an endpoint label like `shisa-hosted-2026-10-10` passes.
  `fixtureProblems` now reads `system_fingerprint` and `created` out of the
  recorded responses and requires the provenance to agree with them. The checks
  return their problems rather than reporting them, so
  `TestFixtureIntegrityChecksCanFail` can run them against mutated copies of the
  provenance; a check nobody has shown to fail is not one.
- `glm`: the fingerprint's "serving shape" check passed the endpoint label it
  exists to reject. The same fix: the check is against the responses.
- `ds4`: `pythonQuote` did not reproduce Python's `repr` escaping for
  non-printable characters, and the comment claimed Go's `strconv.IsPrint` was
  the same set. It is not: Go 1.25's tables are Unicode 15.0.0 and Python
  3.14.6's are 16.0.0, so 5,812 code points assigned since are printable to
  Python and unprintable to Go, and every one was escaped. The predicate is now
  the interpreter's own, from `data/python-printable.json` (736 ranges,
  generated by `scripts/gen_python_printable.py`), and
  `testdata/python_repr.json` replays `repr()` for 32,509 sampled code points.
  Reverting to `strconv.IsPrint` fails the replay on astral code points.
- `ds4` and `glm` independently: the recorded `to_dict` side of the replay was
  rebuilt from the fields `answerFixture` names, so a key the Python client grows
  that this port does not return would be dropped rather than failing the
  comparison. The fixture struct now keeps the recorded object raw and
  `recordedToDict` strips only the `level`, `legend` and `wire` the generator adds
  beside `to_dict`.
- `ds4` and `glm` independently: `CalibrationFromJSON` accepted a record with
  no `temperatures` table, a `null` table, and a `null` per-read table, and
  `PORT.md` called the required keys "what the Python loader indexes" while
  describing a superset. The Python loader reads `record["temperatures"]`
  unconditionally and `dict(None)` raises, so all three are now refused and the
  paragraph says what the loader actually does.
- `ds4`: `PORT.md`'s `CodeRead.Sampled` difference was stale — it described the
  struct field as the only spelling, after the round-1 fix made the raw block
  carry nil — and `CodeRead.Prompt` is the same difference left undocumented. Both
  are now stated, with which of the field and the raw entry carries Go's zero
  value and which carries Python's `None`.

One thing the round did not find, but that the calibration work turned up: the
per-read rule looks like a bug the first time it is read. A record with both a
top-level table and per-read fits ignores the top-level table for a read the
per-read table does not name, returning 1.0 rather than the top-level value. That
is the Python client's `temperature_for`, which returns
`float(self.reads.get(read or "", {}).get(key, 1.0))` and never reaches
`self.temperatures` when `self.reads` is non-empty. The behaviour is right and the
new test was wrong: it asserted 1.89 for a read named `""`. The test now pins 1.0
and says why.

The fixture was not regenerated in this round; the round-1 regeneration still
stands at 24 cases, 35 exchanges, `system_fingerprint: vllm-0.30.0-tp2-ca69195e`.
